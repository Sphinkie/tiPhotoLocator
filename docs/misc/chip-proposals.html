TiPhotoLocator — Propositions d'amélioration des Chips

Trois options indépendantes, combinables entre elles.

État actuel

Tous les chips ont la même couleur BlueGrey Shade400 quelle que soit leur catégorie. L'œil n'a aucun repère visuel pour distinguer un champ GPS d'un keyword ou d'une date.

Option A — Couleur par catégorie Simple

Ajouter une propriété chipColor dans Chips.qml, avec une valeur par défaut calculée depuis target via un switch QML. Les quatre catégories héritent d'une couleur définie dans Style.qml. Les zones qui veulent surcharger peuvent passer la couleur explicitement.

Géolocalisation (Teal)
Photo / IPTC (DeepPurple)
Appareil / EXIF (BlueGrey)
Keywords (Orange)

✔ Un seul changement dans Chips.qml — aucun impact sur les zones appelantes

✔ Le GhostChip reprend automatiquement la couleur du chip source

✘ Les chips de suggestions (SuggestionRepeater) ont déjà leur propre fond bleu clair — vérifier la cohérence


Code dans Chips.qml :

property color chipColor: {
    switch(target) {
        case "latitude": case "longitude":
        case "country": case "city": case "location":
            return Style.chipGeoColor       // Teal 300
        case "keyword":
            return Style.chipKeywordColor   // Orange 300
        case "make": case "model":
        case "aperture": case "speed": case "software":
            return Style.chipCameraColor    // BlueGrey 400 (inchangé)
        default:
            return Style.chipPhotoColor     // DeepPurple 300
    }
}
// Et dans chipRectangle :
color: chipColor

Option B — Bande latérale colorée Simple

Le fond du chip reste neutre (BlueGrey 100 = plus clair qu'actuellement), mais une fine bande de 5px à gauche encode la catégorie. Moins «criard» que l'option A, convient si on veut rester sobre. Implémentation : un Rectangle de 5px en position absolue dans chipRectangle, avec color: chipAccentColor.

Option C — État "modifié" plus visible Simple

Actuellement, canSave met le texte en gras. Deux variantes plus expressives, à choisir :

C1 — Bordure orange
Le fond reste identique, mais une outline colorée (border.color + border.width: 2) signale la modification.

city:Saint-Paul
city:Le Port💾

← intact    modifié →

✔ Peu intrusif, change seulement le contour

C2 — Fond orange
Le chip entier change de couleur quand canSave est vrai. Signal fort.

city:Saint-Paul
city:Le Port💾

← intact    modifié →

✔ Impossible à rater, cohérent avec accentTextColor: DeepOrange déjà dans Style.qml


Code dans Chips.qml (variante C2) :

// Dans chipRectangle :
color: canSave ? Style.chipDirtyColor : chipColor
// Dans Style.qml :
readonly property color chipDirtyColor: Material.color(Material.DeepOrange, Material.Shade300)

Recommandation

Ces trois options sont indépendantes et cumulables. La combinaison la plus efficace pour un minimum d'effort :

  • A + C2 : couleur par catégorie + fond orange sur modification → toute l'information d'état est encodée dans la couleur, sans ajouter un seul widget.
  • Tout se joue dans Chips.qml (propriété chipColor calculée) et Style.qml (4 nouvelles couleurs). Aucun fichier zone à modifier.
